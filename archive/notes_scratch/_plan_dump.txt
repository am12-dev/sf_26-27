How the not-yet-postmenopausal women should be used
The 170 women excluded by the menopause filter are those aged 50–65 who report at least one menstrual period in the preceding twelve months. By the twelve-month amenorrhoea definition they have not reached menopause.
They cannot be classified more precisely than that:
NHANES carries no cycle-regularity item in any of these six cycles —
RHQ040
is absent throughout, and the only period-timing variable that survives for them is
RHQ010
, age at
menarche
— so “perimenopausal” cannot be separated from “premenopausal” in this data. They should be described as
not yet postmenopausal
, which is the strongest claim the data supports, and reported as a characterised excluded group in the attrition table and in Table 1 rather than silently dropped.
They should not enter the primary modelling cohort, and the reason is not statistical taste but a definitional one.
Years since menopause is undefined for 100% of them — 0 of 170 have a usable
RHQ060
, because a woman who has not had her last period has no last period to count from. Including them therefore does not mean imputing a missing value; it means fabricating a menopause date for women who have not had menopause, for every single one of them. That pushes the undefined rate on a primary exposure from 1.9% to 15.8%. What it buys in return is
2 of the 94 osteoporosis events
— because at a median age of 52, with 63% aged 50–52 and a mean T-score 0.67 units healthier, this group is almost event-free on the endpoint the study exists to predict. The defensible use of the 170 is as a pre-specified sensitivity analysis and as a described subgroup, never as part of the population the headline number is computed on.

05
Imputation policy
Two things to be precise about, because they are easy to state loosely.
Median means the 50th percentile of observed values, not the midpoint of the range
The 24 women missing
years_since_menopause
receive
10.0
— the median of the 1,248 observed values — not 21, the midpoint of 0–42. The distinction is large for skewed variables:
met_min_week
would be 720 by median against roughly 21,840 by range-midpoint.
And the median is recomputed
inside each cross-validation fold
, from that fold’s training rows only. Computing it once over the whole dataset leaks test information into training and inflates AUC. The existing
_pipe
already does this correctly and is kept.

06
The analysis cohorts
Each model is reported on the largest cohort its variables permit, rather than forcing one strict cohort on everything.
These cohorts branch rather than nest.
Only C0 contains all the others: C1 and C2 are parallel restrictions that discard
different
cycles — C1 drops 2005–06 for want of activity and supplement data, C2 drops 2017–20 for want of a vitamin D lab file. 170 women sit in C2 but not C1, and 296 sit in C1 but not C2.
Consequence: only within-cohort comparisons are valid
An AUC on C1 and an AUC on C2 describe different populations and must not be read as a progression or compared to each other. Every comparison that carries a claim — the ablation grid, the vitamin D arm, the diabetes strata — holds one cohort fixed and varies only the feature set.

09
Analysis arms
A — Primary. Full feature set, C0 / C1 / C2
All eight models, both cutoffs, nested cross-validation, against OST with a bootstrap ΔAUC confidence interval. This produces the defensible headline number.
What “nested cross-validation” means here
Fitting eight models and reporting the best is biased upward, because the test data helped pick the winner. Nested CV puts the choosing
inside
the scoring: an
outer
loop of 5 folds holds out one fold at a time, and an
inner
loop of 3 folds — run only on the remaining data — selects the model. The inner loop never sees the outer held-out fold, so no test row helps choose the model scored on it.
This is what took the previous osteoporosis figure from 0.833 to 0.806. It is unrelated to the cohort structure in
§06
, which is about
which women
are analysed.
B — Ablation. With and without each variable
The core new deliverable, answering
“how does each model behave with each of these variables, and for categoricals how does it behave without”
. Leave-one-variable-out: refit the full panel with that one column removed and report the change in out-of-fold AUC. Repeated 5-fold CV, not nested, so the grid is affordable; bootstrap intervals only for variables that actually move AUC.

How the code is laid out
One file, run the same way. Internally reorganised into seven blocks, with the variable spec as a declarative table at the top so the whole contract is readable in one screen.

B  VARIABLE SPEC

D  DERIVE

panel, nested CV, ablation grid, strata
G  REPORT

Three structural changes
Inclusion, not exclusion.
define_features
currently subtracts a hand-maintained
exclude
list from every column, so anything BMD-derived leaks unless remembered. The spec in block B is an allowlist — leakage becomes impossible rather than guarded against.
Per-variable missing codes.
Each variable declares its valid range;
recode_refused
’s global replace goes away.
Encoding inside the pipeline.
A
ColumnTransformer
joins imputation and scaling, so categorical encoding is fold-local too.
Dependencies
statsmodels
is
not installed

scipy
is. The adjusted regressions use a numpy least-squares implementation rather than adding a dependency. Nothing new to install, so a fresh clone still runs offline on the committed download caches.
